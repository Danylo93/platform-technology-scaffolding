# __SERVICE_NAME__

Node 22 HTTP service generated by the Platform Engineering Golden Path.

## Local verification

```bash
npm ci
npm test
npm audit --omit=dev --audit-level=high
npm start
```

The service listens on port 8080. GET / identifies the service and environment;
GET /health returns status UP. APP_ENV defaults to local; PORT defaults to 8080.
The Dockerfile installs from the lockfile and runs as the unprivileged node user.

## Delivery

main -> reusable GitHub Actions -> localhost:5000 -> deployment_files -> Argo CD

CI validates, tests, audits, builds a full-SHA image, publishes it, and commits TI
values to deployment_files. Configure a self-hosted runner for this repository
with the platform-lab label, Docker access, Python 3/PyYAML, Helm, kubectl and the
kind-platform-lab context. Node 22 is supplied by the workflow.
Only trusted main pushes and manual dispatches run; PRs never use the local runner.

For a newly created empty GitHub repository:

```bash
git push -u origin deployment_files
git push -u origin main
kubectl apply -f gitops/argocd/app-ti.yaml
```

Argo must have access to git@github.com:__GITHUB_OWNER__/__SERVICE_NAME__.git.
For private repositories configure its repository credentials outside Git.
The initial all-zero image tag is a bootstrap placeholder, not a published image.
The first CI execution replaces TI's tag; HML/PROD receive that image through
promotion. Apply their Applications before dispatching their first promotion:

```bash
kubectl apply -f gitops/argocd/app-hml.yaml
kubectl apply -f gitops/argocd/app-prod.yaml
```

Run the Promote image workflow on main, choose hml and the current TI SHA;
after success, run it for prod with that same SHA. Promotion never rebuilds.
Applications use __SERVICE_NAME__-ti/hml/prod and shared platform-ti/hml/prod
namespaces. Kubernetes pulls from platform-registry:5000, not localhost:5000.

## Helm and access

```bash
helm lint gitops/chart -f gitops/environments/ti/values.yaml
helm template __SERVICE_NAME__ gitops/chart -f gitops/environments/ti/values.yaml
kubectl port-forward -n platform-ti svc/__SERVICE_NAME__ 8080:8080
```

Routes are disabled for Kind. Resources request 25m CPU/32Mi RAM and limit each
container to 250m CPU/96Mi RAM. TI/HML/PROD use 1/2/3 replicas respectively.
Argo has automated sync and selfHeal enabled. Change desired state in Git.
